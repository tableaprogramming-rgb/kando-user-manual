## 📋 DOCUMENTATION & QUESTIONNAIRE (3 days before)

### Questionnaire Review
- [ ] Client questionnaire received and reviewed
- [ ] All mandatory sections are completed
- [ ] Flagged items requiring clarification
- [ ] Identified complexity level (Low/Medium/High)
- [ ] Noted any missing information

### Clarifications Sent (if needed)
- [ ] Clarification email sent to client (with specific questions)
- [ ] Responses received and documented
- [ ] Ambiguities resolved in writing
- [ ] Backup assumptions documented (if any answers still unclear)

### Risk Assessment
- [ ] Complex features identified (unusual policies, integrations, etc.)
- [ ] Escalation items flagged (if any to implementation team)
- [ ] Timeline for escalation items understood
- [ ] Client expectations set for what can/can't be done in training

---

## 🎓 TRAINING CONTENT PREPARATION (2 days before)

### Create Training Narrative
- [ ] Welcome & intro prepared (match their org size/industry)
- [ ] Opening hook: Why Kando solves their specific challenge
- [ ] Session roadmap created based on their questionnaire responses
- [ ] Closing summary & next steps outlined
- [ ] Time allocation per section planned

### Customize Examples & Scenarios
- [ ] Real employee names/scenarios created from their org structure
- [ ] Leave types examples match their actual policies
- [ ] Pay component examples match their salary structure
- [ ] Shift examples match their work schedules
- [ ] Approval workflows match their reporting structure
- [ ] Screenshots/demo flows annotated with their terminology

**Example Scenario Template:**
```
"Jane is in [Department], reports to [Manager].
She works [Schedule type].
She takes [Leave type].
She earns [Compensation].
Her approval chain: [Chain]."
```

## 💻 DEMO ENVIRONMENT SETUP (1-2 days before)

### Test Account Access

- [ ] Access to all necessary sections confirmed

### Create Demo Data

- [ ] Leave types configured as they specified
- [ ] Shift/schedule templates created per their types
- [ ] Pay components set up matching their structure

- [ ] Reporting relationships established
- [ ] Sample leave requests in various states (pending, approved, rejected)
- [ ] Sample timelogs showing different scenarios

**Demo Data Checklist:**
```
□ Manager: Alice
  ├─ Can view & approve requests
  ├─ Has team: Bob & Carol
  ├─ Can access reports
  └─ Views dashboard

□ Employee: Bob
  ├─ Clock in/out capability
  ├─ View schedule
  ├─ Request leave
  └─ View payslip

□ Employee: Carol (Remote/different shift)
  ├─ Clock in/out (web only)
  ├─ Different shift pattern
  ├─ Flexible hours setup
  └─ Project tracking (if applicable)
```

## 🎯 TRAINING CONTENT STRUCTURE

### Session Outline (based on their questionnaire)

**Opening (5 mins)**
- [ ] Welcome & introductions
- [ ] Training objectives (what they'll be able to do after training)
- [ ] Agenda overview
- [ ] Q&A ground rules

**Foundation (10 mins)**
- [ ] System overview & navigation
- [ ] Their org structure in the system
- [ ] Role-based access (what they'll see based on role)

**Core Features (60-80% of time, customize per their needs)**

**If focusing on Time Tracking** (20-30 mins)
- [ ] Time tracking methods (web vs. kiosk vs. mobile)
- [ ] Creating shifts and schedules
- [ ] Employee clock in/out demo using their shift types
- [ ] Viewing and correcting timelogs
- [ ] Reports/dashboards

**If focusing on Leave Management** (20-30 mins)
- [ ] Their leave policies configured
- [ ] Employee leave request flow
- [ ] Manager approval workflow
- [ ] Viewing leave balance
- [ ] Reports on leave usage

**If focusing on Payroll** (20-30 mins)
- [ ] Compensation components configured
- [ ] Pay period configuration
- [ ] Viewing payslips
- [ ] Overtime and deductions handling
- [ ] Reports

**If focusing on Schedules** (15-25 mins)
- [ ] Creating shift patterns
- [ ] Assigning to departments/employees
- [ ] Schedule swaps and time-off requests
- [ ] Schedule visibility for employees

**Specific to Their Setup** (10-20 mins)
- [ ] Approval workflows matching their structure
- [ ] Custom fields or special configurations
- [ ] Integration points (if applicable)
- [ ] Compliance considerations

**Closing (5-10 mins)**
- [ ] Review of key takeaways
- [ ] Demo data recap
- [ ] Next steps (UAT, data migration, go-live)
- [ ] Support contacts
- [ ] Q&A

## 🧪 TESTING SCENARIOS (Practice before training)

Run through these scenarios in your demo:

### Scenario 1: Employee Daily Flow
```
1. Alice (employee) clocks in at 8:55 AM
   → Expected: On-time arrival, shift active
2. Bob (employee) clocks in at 8:05 AM
   → Expected: Shows as LATE (if grace < 5 mins)
3. Carol requests 2 days annual leave
   → Expected: Request created, pending manager approval
```

### Scenario 2: Manager Approval
```
1. Manager views pending leave requests
   → Expected: Shows Carol's request, with approve/reject buttons
2. Manager approves Carol's leave
   → Expected: Status changes to approved, Carol can see it
3. Manager views team's timelogs
   → Expected: Shows daily clock in/out, hours worked
```

### Scenario 3: Payroll Preparation
```
1. View payroll period setup
   → Expected: Shows their pay frequency (weekly/monthly/etc.)
2. View employee compensation
   → Expected: Shows all components (base, allowances, deductions)
3. Generate payroll report
   → Expected: Summary of all payments for period
```

### Scenario 4: Reporting
```
1. Generate attendance report
   → Expected: Shows presence/absence by employee
2. Generate leave report
   → Expected: Shows leave types and balances
3. Generate payroll summary
   → Expected: Shows total compensation by department
```

## 📌 QUICK REFERENCE: COMMON ISSUES & SOLUTIONS

**If Demo System Doesn't Load**
```
→ Check internet connection
→ Try alternate browser
→ Use backup demo account
→ Fall back to live slides/screenshots
→ Reschedule 30 minutes if critical
```

**If Participant Can't Access**
```
→ Verify login credentials
→ Check their internet
→ Send fresh reset link
→ Use screen sharing alternative
→ Move them to observer role
```

**If Question Seems Out of Scope**
```
→ "Great question! That's beyond our training scope,
   but I'm noting it for our implementation team.
   We can discuss post-training."
→ Document and escalate
```

**If Time Running Short**
```
→ Prioritize core sections
→ Skip nice-to-have features
→ Offer follow-up sessions
→ Provide recorded demo
→ Create self-paced guide
```
