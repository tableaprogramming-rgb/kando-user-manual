# System Setup Requirements

*Before employees and managers can use Kando, your system administrator must configure several things. This guide explains what needs to be set up and in what order.*

## Overview

Kando requires initial configuration before any users can clock in, request leave, or process payroll. The **order of setup matters** — some configurations depend on others being created first.

This guide is for system administrators and HR leads setting up Kando for the first time.

### Setup Timeline

- **Quick setup** (just employees): 2-4 hours
- **Full setup** (with all features): 6-8 hours
- **First configuration** (new organization): 4-6 hours

## What Needs to Be Configured

Before employees can use Kando, you must set up:

| Phase | What | Who | Why |
|-------|------|-----|-----|
| **1. Foundation** | Organization, access groups | Admin | Required for all users |
| **2. Users** | Employee records, managers | HR Admin | Employees need accounts |
| **3. Leave System** | Leave types, leave credits | HR Admin | Before leave requests work |
| **4. Scheduling** | Shift types, employee schedules | Manager | Before clock-in works |
| **5. Payroll** | Pay cycles, pay types, compensation | HR Admin | Before payroll works |

## Phase 1: Organization & Access Groups Setup

*Estimated Time: 30-45 minutes*

This is the foundation. Everything else depends on these configurations.

### Step 1.1: Verify Organization Exists

1. Log in as Owner or Administrator
2. Go to **Settings** → **Organization**
3. Verify your organization name is correct
4. Check timezone is set correctly (affects timesheets and payroll)

**Why it matters**: All users must belong to an organization. Timezone affects time tracking and scheduling.

### Step 1.2: Understand Access Groups

Kando has four default access groups. Each has different permissions:

| Access Group | Can Do | Used For |
|--------------|--------|----------|
| **Owner** | Everything | Company leadership, finance, system admin |
| **Manager** | Approve requests, manage team, create schedules | Department/team leads |
| **HR Admin** | Configure policies, create users, manage payroll | HR department staff |
| **Employee** | Clock in, request leave, view own data | All other staff |

**Important**: Users can only do what their access group allows. A manager without "Manager" group cannot approve requests.

### Step 1.3: Verify Access Groups Are Configured

1. Go to **Settings** → **Access Groups** (or **Roles**)
2. Confirm these exist:
   - ✅ Owner
   - ✅ Manager
   - ✅ HR Admin
   - ✅ Employee

**Note**: These are usually created by default. If any are missing, contact support.

## Phase 2: Create Users & Employees

*Estimated Time: 1-2 hours (depends on number of users)*

Users need accounts before they can login.

### Step 2.1: Plan Your Users

Make a list of:
- All employees who need access
- Their roles (Owner, Manager, HR Admin, or Employee)
- Their email addresses (for login)
- Who their manager is (if applicable)

### Step 2.2: Create User Accounts

1. Go to **Settings** → **Users** or **Administration** → **Users**
2. Click **Add New User** or **Create User**
3. Enter:
   - **Email**: User's work email (used for login and notifications)
   - **Name**: First and last name
   - **Username**: Usually same as email or employee ID
   - **Temporary Password**: System generates or you enter one
   - **Access Group**: Select their role (Owner, Manager, HR Admin, or Employee)
4. Click **Create User**

**What happens next**:
- User receives email with login link and temporary password
- User logs in and changes password
- User completes profile setup (address, phone, bank details)

### Step 2.3: Create Employee Records

**Important**: Each employee needs an Employee record (separate from User account).

1. Go to **Settings** → **Employees** or **Administration** → **Employees**
2. Click **Add Employee** or **Create Employee**
3. Enter:
   - **Employee ID**: Unique identifier (badge number, etc.)
   - **User**: Link to the user account you created above
   - **Department**: Which department/team
   - **Manager**: Who is their direct manager
   - **Start Date**: When they started
   - **Status**: Active
4. Click **Create**

**Why it matters**:
- Users can't clock in or request leave without an Employee record
- Manager field is required for leave approvals
- Department field is used for reporting

### Step 2.4: Assign Managers

For each employee (except top leadership):
1. Go to **Employees** → Find the employee
2. Set the **Manager** field to their direct supervisor
3. Save

**Why it matters**: Employees' leave requests go to this manager for approval.

## Phase 3: Leave System Setup

*Estimated Time: 1-2 hours*

Before employees can request leave, you must set up leave types and their balances.

### Step 3.1: Create Leave Types

1. Go to **Settings** → **Leave Types** or **Administration** → **Leave Management** → **Leave Types**
2. Click **Add Leave Type** or **Create Leave Type**
3. For each leave type (Vacation, Sick Leave, Personal, etc.):
   - **Name**: "Vacation Leave" (visible to employees)
   - **Code**: "VAC" (internal identifier)
   - **Is Paid**: Yes (for most types)
   - **Annual Allocation**: How many days per year (e.g., 20)
   - **Can Carry Over**: Yes/No (policy dependent)
   - **Status**: Active
4. Click **Create**

**Common leave types to create**:
- Vacation Leave / Annual Leave (20-30 days)
- Sick Leave (5-10 days)
- Personal Leave (2-5 days)
- Bereavement Leave (3-5 days)
- Unpaid Leave (optional)

**Why it matters**: Employees can only request leave types that exist.

### Step 3.2: Initialize Leave Credits

**Critical**: Each employee must have a Leave Credit record for each leave type, or they cannot request that type.

1. Go to **Settings** → **Leave Credits** or **Employees** → Select employee → **Leave**
2. For each employee and each leave type:
   - Add Leave Credit with:
     - **Employee**: Select employee
     - **Leave Type**: Select the leave type you created
     - **Balance**: Number of days for this year (e.g., 20 days for Vacation)
     - **Effective Date**: When this balance starts
3. Click **Save**

**Why it matters**:
- Without a credit record, employee cannot request that leave type
- System prevents over-requesting using credit balance
- Balance is auto-deducted when leave is approved

**Alternative**: Some systems auto-create credits based on configuration. Check if yours has this feature.

### Step 3.3: Configure Approval Rules (Optional)

Leave requests can either:
- **Auto-approve** immediately (deduct leave automatically)
- **Require approval** from manager
- **Require multi-level approval** (manager AND HR)

1. Go to **Settings** → **Approval Rules** or **Administration** → **Workflows** → **Approval Rules**
2. Create or verify approval rules for leave requests
3. For each rule, specify:
   - **Applies to**: Leave requests
   - **Approvers**: Who must approve (manager, HR admin, both)
   - **Auto-approve if**: Any conditions for instant approval

**If unsure**: Default is "manager approval" which is safest.

## Phase 4: Scheduling Setup

*Estimated Time: 1-3 hours (depends on complexity)*

Before employees can clock in, they need schedules created.

### Step 4.1: Create Shift Types (If Using Shifts)

If your organization uses shifts (day shift, night shift, etc.):

1. Go to **Settings** → **Shift Types** or **Administration** → **Scheduling** → **Shift Types**
2. For each shift type:
   - **Name**: "Day Shift", "Night Shift", etc.
   - **Start Time**: 09:00 AM
   - **End Time**: 05:00 PM
   - **Duration**: Auto-calculated
   - **Break Time**: Duration of breaks (if configured)
3. Click **Create**

**If using flexible hours** (no fixed shifts):
- You may skip this step or create a "Flexible" shift type

### Step 4.2: Assign Schedules to Employees

Employees cannot clock in without a schedule for that date.

1. Go to **Schedule** → **Employee Schedules** or **Administration** → **Scheduling**
2. For each employee, create schedules:
   - **Date**: When they work
   - **Shift Type**: Which shift (if using shifts)
   - **Status**: Active
3. Click **Save**

**Best practice**:
- Create schedules in batches (weekly or monthly)
- Can create recurring schedules if using template
- Managers should create schedules for their teams

**Why it matters**:
- Employee cannot clock in without a schedule for that date
- Clock-in time must be within schedule boundaries
- Used for calculating overtime and undertime

## Phase 5: Payroll Setup

*Estimated Time: 1.5-2 hours*

Payroll requires several interconnected configurations.

### Step 5.1: Create Payroll Cycles

1. Go to **Settings** → **Payroll Cycles** or **Administration** → **Payroll** → **Cycles**
2. Create cycles for your organization:
   - **Name**: "Monthly", "Bi-weekly", etc.
   - **Frequency**: Monthly, Bi-weekly, Weekly
   - **Cycle Days**: Which days of the month (e.g., 1-30 for monthly)
   - **Status**: Active
3. Click **Create**

**Common cycles**:
- Monthly (1-30/31)
- Bi-weekly (1-14, 15-30)
- Weekly (Monday-Sunday)

### Step 5.2: Assign Employees to Cycles

1. Go to **Employees** → Select employee
2. Assign to Payroll Cycle:
   - **Payroll Cycle**: Select the cycle they follow (e.g., "Monthly")
   - **Period**: Select which period header
   - **Status**: Active
3. Click **Save**

**Why it matters**: System uses this to determine which timesheet period belongs to which payroll run.

### Step 5.3: Create Pay Types

1. Go to **Settings** → **Pay Types** or **Administration** → **Payroll** → **Pay Types**
2. Create pay types:
   - **Name**: "Monthly Salary", "Hourly", etc.
   - **Frequency**: How often employees with this type are paid
   - **Fields**: Configure which fields appear on payslip
     - Basic salary
     - Overtime pay
     - Deductions
     - Taxes
3. Click **Create**

### Step 5.4: Collect Employee Compensation Data

For each employee, collect:
- **Bank account details** (for direct deposit)
  - Account holder name
  - Account number
  - Bank name
  - Account type (checking/savings)
  - Routing number (if applicable)
- **Tax information** (BIR form, TIN, etc.)
- **Salary/hourly rate**
- **Allowances** (if any)
- **Deductions** (if any)

Employees can often enter this in their own profile:
1. Have employees log in
2. Go to **Settings** → **Compensation** or **Profile**
3. Enter bank details and tax information
4. Save

**Why it matters**:
- Bank details required for direct deposit payment
- Tax info needed for tax calculations
- Salary is basis for payroll calculations

### Step 5.5: Configure Pay Cycles & Periods

Create calendar periods for payroll:

1. Go to **Settings** → **Periods** or **Administration** → **Payroll** → **Periods**
2. Create periods:
   - **Start Date**: First day of period
   - **End Date**: Last day of period
   - **Payroll Date**: When payment is made
   - **Status**: Active
3. Repeat for each payroll period (monthly, bi-weekly, etc.)

**Why it matters**: Used to match timesheets to payroll runs.

## Verification Checklist

Before declaring setup complete, verify:

### Access & Users
- ✅ Organization is active and timezone is correct
- ✅ All access groups exist (Owner, Manager, HR Admin, Employee)
- ✅ All users have accounts created
- ✅ All users have Employee records created
- ✅ All managers are assigned to employees

### Leave System
- ✅ All leave types are created (Vacation, Sick, Personal, etc.)
- ✅ Each employee has Leave Credit for each leave type
- ✅ Leave balances match company policy
- ✅ Approval rules configured (or using defaults)

### Scheduling
- ✅ Shift types created (if using shifts)
- ✅ Schedules created for all employees
- ✅ Schedules are for appropriate dates/times

### Payroll
- ✅ Payroll cycles created
- ✅ All employees assigned to cycles
- ✅ Pay types created
- ✅ Employees have bank details entered
- ✅ Tax information configured

## Testing the Setup

### Test 1: Employee Can Log In
1. Have a test employee log in
2. Verify they see Dashboard
3. Verify they see correct role/access

**Expected**: Employee sees employee-level dashboard

### Test 2: Employee Can Clock In
1. Employee clicks **Clock In**
2. Verify clock-in is successful
3. Check **Time** section shows the clock-in entry

**If fails**:
- ❌ Employee doesn't have a Schedule for this date
- ❌ Schedule doesn't match current time
- ❌ Timesheet is already approved

### Test 3: Employee Can Request Leave
1. Employee clicks **Request Leave**
2. Try to request leave
3. Verify leave type dropdown shows available types

**If fails**:
- ❌ Employee doesn't have Leave Credit for that type
- ❌ Employee has zero balance
- ❌ Leave type not created

### Test 4: Manager Can Approve
1. Employee requests leave
2. Have manager log in
3. Verify manager sees the request under **Pending Approvals**

**If fails**:
- ❌ Manager not assigned to employee
- ❌ Manager doesn't have "Manager" access group
- ❌ Approval rule not configured

## Common Setup Mistakes

### ❌ "Employees Can't Clock In"
**Cause**: No schedule created for that employee/date

**Solution**:
1. Go to **Scheduling**
2. Create a schedule for the employee for that date
3. Employee can then clock in

### ❌ "Can't Request Leave"
**Cause**: No Leave Credit created for that employee

**Solution**:
1. Go to **Leave Credits**
2. Create a credit for employee + leave type
3. Employee can then request that leave type

### ❌ "Manager Can't Approve Requests"
**Cause**: Manager not in approvers list or not assigned access group

**Solution**:
1. Verify manager has "Manager" access group
2. Verify employee is assigned to this manager
3. Verify approval rule is configured

### ❌ "User Can't Log In"
**Cause**: Email not verified or no access group assigned

**Solution**:
1. Verify user's email is verified
2. Verify user has access group assigned (Owner, Manager, HR Admin, or Employee)
3. User may need to check email for verification link

### ❌ "Can't Process Payroll"
**Cause**: Missing cycle, period, or pay type

**Solution**:
1. Verify payroll cycles are created
2. Verify periods/dates are set up
3. Verify pay types are configured
4. Verify all employees are assigned to cycles

## Best Practices

✅ **DO**:
- Create a test user to verify setup before full rollout
- Document your configuration (especially approval rules)
- Create schedules in batches (weekly/monthly)
- Ask employees to enter their own bank details (they'll be current)
- Assign clear managers for each employee
- Test leave requests before communicating to employees
- Keep access groups and permissions organized

❌ **DON'T**:
- Create users before creating their manager (circular dependency)
- Forget to initialize Leave Credits (employees will get errors)
- Create overlapping or conflicting schedules
- Assign employees to multiple cycles (one cycle per employee)
- Skip timezone configuration (affects all time tracking)
- Create sensitive leave types without approval rules
- Forget to activate users and access groups
