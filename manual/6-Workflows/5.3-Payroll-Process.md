# Payroll Process Workflow

*Complete guide to understanding how payroll works, from timesheet submission through payment and period locking.*

## Overview

The payroll process is the complete cycle of:
1. Employees tracking work time
2. Managers approving timesheets
3. Payroll team calculating salaries
4. Payments being made
5. Period being locked to prevent changes

This workflow ensures accurate, timely compensation and maintains financial integrity.

## Key Concept: Period Locking

**What is a Payroll Period?**

A payroll period is a defined time window (usually 1 month) for which:
- Employees clock in and work
- Managers approve timesheets
- Payroll calculates salaries
- Payments are processed
- Then the period is "locked" to prevent changes

**Once Locked**: No modifications can be made to that period's data.

## Complete Payroll Workflow Timeline

```
MONTH 1 (January)
├─ Jan 1-31: ACTIVE PERIOD
│  ├─ Employees work and clock in/out
│  ├─ Managers can approve timesheets
│  ├─ Employees can request leave
│  └─ Entries are editable
│
├─ Feb 1: Payroll Closes
│  ├─ All timesheets due
│  ├─ No new entries accepted
│  ├─ Payroll team begins processing
│  └─ Period is "PROCESSING"
│
├─ Feb 2-3: Payroll Calculates
│  ├─ All hours, leave, deductions calculated
│  ├─ Salary determined for each employee
│  ├─ Tax and benefits computed
│  └─ Still may allow corrections (depends on company)
│
├─ Feb 5: Period LOCKED (Payroll Finalized)
│  ├─ Salaries confirmed
│  ├─ All data read-only
│  ├─ No edits possible
│  └─ Payments ready to process
│
└─ Feb 8: Salaries PAID
   ├─ Payments deposited
   └─ Employees see payslips

MONTH 2 (February)
├─ Jan period LOCKED (can't change anything from January)
├─ Feb 1-28: NEW ACTIVE PERIOD (can work and modify)
└─ All new entries in February work normally
```

## People Involved in Payroll

| Role | Responsibility | When Active |
|------|-----------------|------------|
| **Employee** | Work, clock in/out, submit timesheet | Days 1-last of month |
| **Manager** | Review and approve employee timesheets | Days 1-last of month |
| **HR/Payroll Team** | Process salaries, handle exceptions | Last 1-2 days + lock date |
| **Finance/Accountant** | Verify and post to accounting system | Lock date |
| **Executive** | Approve payroll (sometimes) | Lock date |

## Step-by-Step Payroll Process

### Week 1-3: Active Period (Everything Normal)

**During the active period, the system works normally:**

✅ Employees can:
- Clock in and out
- Edit time entries
- Request leave
- Add manual entries

✅ Managers can:
- Approve timesheets
- Request changes from employees
- Create manual entries for team
- Modify schedules

✅ System Features:
- All entries editable
- New requests accepted
- Leave deductions applied
- Corrections easy

### Week 4: Period Closing Phase

**As month ends, payroll team prepares:**

**Timeline** (typically last 2-3 days of month):
1. **Day 28-29**: Final timesheet due
2. **Day 29-30**: Payroll reviews all submissions
3. **Day 30-31**: Payroll locks the period
4. **Day 1-5 next month**: Salaries deposited

**What Changes at Close**:
- ⚠️ No new timesheets accepted
- ⚠️ Entries may not be editable
- ⚠️ Leave requests for that period rejected
- ⚠️ But corrections may still be possible (depends on company policy)

### Understanding Period Locking

#### What Does "Period Locked" Mean?

**Locked Period** = Read-only, no modifications allowed

Once payroll is calculated and finalized:
- ✅ You can VIEW all past data
- ❌ You CANNOT edit anything
- ❌ You CANNOT add new entries
- ❌ You CANNOT request leave for those dates
- ❌ You CANNOT delete entries

**Why Lock It?**

Locked periods protect:
1. **Payroll Accuracy**: Salary was calculated based on this data
2. **Audit Trail**: Immutable records for compliance
3. **Data Integrity**: Prevents accidental or intentional changes
4. **Legal Compliance**: Employment laws require frozen payroll records
5. **Finance Records**: Accounting needs permanent records

**Real Example**:
```
Your January timesheet is locked on Feb 5 after payroll processes.
Your salary is determined: 160 hours × PHP 200 = PHP 32,000
You're paid PHP 32,000 on Feb 8.

If you could change January after lock:
- You could add 10 hours retroactively
- Your pay would need adjustment
- It would mess up accounting records
- Creates audit and legal issues

Solution: Lock the period so data can't be changed after pay is determined
```

#### Error: "Period is already locked"

**What This Means**: You tried to make a change to a locked payroll period.

**Common Scenarios**:

1. **Tried to clock in for past month**:
   ```
   You: Try to clock in for January 15 (it's now February 10)
   System: "Period is already locked"
   Reason: January period was locked on Feb 5, no changes allowed
   ```

2. **Tried to request leave for past month**:
   ```
   You: Try to request leave for Jan 20 (it's now February 15)
   System: "Period is already locked"
   Reason: Can't request leave for months that are locked
   ```

3. **Tried to edit time entry**:
   ```
   You: Try to change Jan 10 time from 9:00 to 8:30 (it's Feb)
   System: "Period is already locked"
   Reason: All January data is locked, can't modify
   ```

### How to Handle Locked Period Issues

#### Scenario 1: Found Error in Locked Period

**Situation**: "My January timesheet shows wrong hours but period is locked"

**What You CAN'T Do**:
- ❌ Edit the entry yourself
- ❌ Delete the entry
- ❌ Modify dates or times

**What You CAN Do**:
1. **Contact your manager**: "I noticed error in my Jan 15 entry"
2. **Manager escalates to HR/Payroll**: They can unlock or adjust
3. **HR creates a Payroll Adjustment**:
   - They review the error
   - Create formal adjustment request
   - Adjust salary if error was significant
   - Add note to audit trail
4. **You're notified**: New payslip issued if pay changes

**Timeline**: Usually 1-2 days for correction

**Example**:
```
You: "I worked 10 hours on Jan 15 but system shows 8"
Manager: "Let me check. Confirmed - error in system"
Manager → HR/Payroll: "Please adjust Jan 15 from 8 to 10 hours"
HR/Payroll: Reviews, approves, creates adjustment
You: Receive updated payslip with +2 hours pay
```

#### Scenario 2: Need to Add Hours to Locked Period

**Situation**: "I forgot to clock in for January 10"

**If Period is STILL ACTIVE** (same month):
- ✅ Easy: Add manual time entry yourself
- Notified manager and it's approved

**If Period is LOCKED** (past month):
- ❌ Can't add it yourself
- ✅ Manager/HR must create adjustment
- May require additional documentation

**Process**:
1. Notify manager ASAP: "Realized I forgot to clock in for Jan 10"
2. Manager reviews: "OK, I can create adjustment"
3. Manager escalates to HR: "Add 8 hours to Jan 10 for John"
4. HR creates adjustment: Adds hours + updates pay
5. You receive adjusted payslip

**Prevention**: Clock in/out daily. Don't wait until month ends.

#### Scenario 3: Timesheet Reversal

**Situation**: "I made a mistake in my January timesheet, need to reverse it"

**What Reversal Means**: Manager completely undoes a posted/finalized timesheet

**When Available**:
- Only for timesheets that have been finalized
- Only manager or HR can initiate
- Creates audit trail of reversal

**Process**:
1. Manager reviews the timesheet
2. Manager clicks "Reverse Timesheet" in Payroll Admin
3. System:
   - Marks original as "Reversed"
   - Removes hours from that period
   - Adjusts salary downward
   - Creates new payslip with reduced pay
4. Employee is notified: "Your Jan timesheet has been reversed. New payslip issued."

**Important**:
- Reversal happens AFTER payroll was already processed
- May require tax adjustment, deduction recalculation
- Creates formal audit record
- Used only when serious errors exist

### Timeline and Key Dates

**Monthly Payroll Cycle**:

```
Day 1-28/29/30/31: ACTIVE PERIOD
├─ Employees work normally
├─ Managers approve timesheets
├─ Entries are editable
└─ Leave requests accepted

Last 2 days of month: CLOSING PHASE
├─ Final timesheets submitted
├─ Payroll reviews all data
├─ May allow last-minute corrections
└─ Period transitions to "Processing"

Day 1-3 next month: LOCKED PERIOD
├─ Payroll finalized
├─ All data read-only
├─ Payments processed
└─ Employees paid

Day 5-10 next month: POST-PAYMENT
├─ Payslips available
├─ Adjustments can be requested
├─ Corrections filed by HR
└─ Month fully closed
```

### Tips for Avoiding Period Locking Issues

✅ **DO**:
- **Submit timesheets on time**: Don't wait until last day of month
- **Review entries daily**: Catch errors while period is active
- **Request corrections early**: Notify manager of errors immediately
- **Request leave within the month**: Before period locks
- **Clock in/out same day**: Don't add entries retroactively
- **Save manual entries**: Keep documentation if manager created entry for you
- **Note discrepancies**: If hours don't match expectations, investigate

❌ **DON'T**:
- Don't try to edit past months after they're locked
- Don't wait until month-end to request leave
- Don't ignore timesheet notifications
- Don't assume you can change locked period data
- Don't delay requesting corrections
- Don't work without clocking in (hard to fix later)
- Don't request retroactive entries after long delays

### Understanding Your Organization's Payroll Calendar

**Different companies have different calendars:**

| Organization | Period | Lock Date |
|--------------|--------|-----------|
| **Company A** | Monthly (1st-last) | 5th of next month |
| **Company B** | Biweekly (1-15, 16-31) | 3rd day after period ends |
| **Company C** | Weekly (Mon-Sun) | Wednesday of next week |

**Action**: Ask your manager or HR:
- When is YOUR payroll period? (dates)
- When does YOUR period lock? (date)
- Can changes be made after lock? (policy)
- Who handles adjustments? (HR or Payroll)

### What Happens After Period Locks

**For Employees**:
- View payslips (read-only)
- Request adjustments (through manager)
- View historical data
- Can't make changes

**For Managers**:
- View team payroll (read-only)
- Request adjustments (to HR/Payroll)
- Generate payroll reports
- Access audit trail

**For HR/Payroll**:
- Create formal adjustments
- Process corrections
- Reverse timesheets (if necessary)
- Handle exceptions
- Maintain audit trail
